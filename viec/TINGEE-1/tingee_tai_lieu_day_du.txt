Giới thiệu
Để triển khai tích hợp với hệ thống Tingee, đối tác bắt buộc phải sử dụng Client ID và Secret Token và Sinh chữ ký nhằm xác thực và đảm bảo tính hợp lệ cho mỗi yêu cầu API.
Tài liệu này hướng dẫn chi tiết cách truy xuất các thông tin trên cho từng tài khoản đối tác.

Hướng dẫn lấy Client ID & Secret Token
Bước 1. Truy cập vào hệ thống Tingee BaaS Portal (hoặc trang thử nghiệm uat-baas-portal.tingee.vn) và đăng ký/đăng nhập tài khoản của Đối tác.

Bước 2. Tại menu Sidebar bên trái, click chọn mục API Credentials (hoặc truy cập trực tiếp tại baas.tingee.vn/api-credentials). 

Bước 3. Nhấp vào nút Tạo mới (hoặc Tạo mới API Credentials) để mở modal tạo bộ xác thực:

Thông tin cơ bản: Điền Tên gợi nhớ (để phân biệt mục đích sử dụng, ví dụ: Live Credentials, POS Test, Mobile App...) và Mô tả.
Quyền truy cập: Chọn nhóm sản phẩm/dịch vụ mà Credentials này được phép gọi API (Cổng thanh toán, QR, Bank Link, Direct Debit, v.v., hoặc click chọn Chọn tất cả). 
Bước 4. Bấm nút Tạo API Credentials để lưu cấu hình. Hệ thống sẽ tạo bộ thông tin định danh và hiển thị tại danh sách gồm Client ID và Secret Token. Đối tác dùng nút Sao chép (copy) để lấy các thông tin này đưa vào cấu hình tích hợp.

Sinh chữ ký Signature
Mỗi API request gửi đến Tingee cần kèm theo chữ ký số (signature) để đảm bảo tính toàn vẹn và xác thực danh tính đối tác.

Công thức sinh chữ ký
x-signature = HMAC_SHA512( x-request-timestamp + ":" + requestBody, secretToken )

Trong đó:

x-request-timestamp — Thời điểm gửi request, format yyyyMMddHHmmssSSS (múi giờ UTC+7)
requestBody — Chuỗi JSON của request body, đã qua JSON.stringify() (minified, không có khoảng trắng thừa)
secretToken — Secret Token lấy từ trang Developers của tài khoản đối tác
Headers bắt buộc
Header	Bắt buộc	Ví dụ
x-client-id	✅	Mã định danh của đối tác do TINGEE cung cấp
Xem cách lấy tại đây
x-request-timestamp	✅	20260101101122333
x-signature	✅	Chữ ký SHA-512
Content-Type	✅	application/json
Code mẫu
Node.js
C#
Java
PHP
const crypto = require('crypto');

function generateSignature(timestamp, requestBody, secretToken) {
  const message = `${timestamp}:${requestBody}`;
  return crypto
    .createHmac('sha512', secretToken)
    .update(message, 'utf8')
    .digest('hex');
}

// Ví dụ sử dụng
// Timestamp theo múi giờ UTC+7 (cộng 7 giờ vào giờ UTC)
const timestamp = new Date(Date.now() + 7 * 60 * 60 * 1000)
  .toISOString()
  .replace(/[-:T.Z]/g, '')
  .slice(0, 17); // "yyyyMMddHHmmssSSS"

const body = JSON.stringify({ clientId: 'abc123', amount: 50000 });
const signature = generateSignature(timestamp, body, 'YOUR_SECRET_TOKEN');

// Gắn vào headers khi gọi API
const headers = {
  'Content-Type': 'application/json',
  'x-client-id': 'YOUR_CLIENT_ID',
  'x-request-timestamp': timestamp,
  'x-signature': signature,
};

Lưu ý quan trọng
Không chia sẻ secretToken trong mã nguồn hoặc repository công khai.
Timestamp không được vượt quá thời điểm hiện tại và không được cũ hơn 10 phút so với thời gian máy chủ Tingee (UTC+7).
requestBody phải là kết quả của JSON.stringify(body) — chuỗi JSON minified, không thêm khoảng trắng hay format lại, để đảm bảo chữ ký khớp chính xác.

Dùng Postman Collection
Tải file Postman Collection ở bảng trên, mở Postman và chọn Import.
Trong tab Variables của collection, điền clientId và secretKey lấy từ trang quản lý API Key.
Biến baseUrl mặc định là môi trường UAT (https://uat-open-api.tingee.vn). Đổi thành https://open-api.tingee.vn khi gọi PROD.
Chọn request bất kỳ và bấm Send — không cần tự tính chữ ký.

Cấu hình Webhook
Tingee sẽ gửi các Requests HTTP (method POST) đến Webhook url của Đối tác khi phát sinh giao dịch với các tài khoản liên kết trên Tingee.

Đối tác cấu hình và quản lý tại mục Webhook trên menu Sidebar của Portal: 

Nhấn nút Tạo mới để mở modal cấu hình endpoint nhận sự kiện:

Thông tin cơ bản:
Tên endpoint: Nhập tên gợi nhớ.
URL webhook endpoint: Nhập địa chỉ HTTP/HTTPS nhận dữ liệu. Đối tác có thể bấm Kiểm tra kết nối (Connection Test) để kiểm tra tính khả dụng của URL.
Phạm vi sự kiện: Chọn nhóm sự kiện muốn nhận thông báo (ví dụ: QR Code).
Nếu chọn QR Code, chọn Loại áp dụng:
Tất cả: Nhận sự kiện với mọi tài khoản.
Số tài khoản ảo: Chọn các tài khoản cụ thể muốn nhận sự kiện.
Cửa hàng: Chọn các cửa hàng cụ thể muốn nhận sự kiện.
Đồng thời có thể thiết lập Danh sách đen (Blacklist) để loại trừ các số tài khoản không muốn gửi webhook.
Cấu hình gọi lại webhook (Retry): Bật/tắt retry, thiết lập điều kiện gửi lại (timeout, lỗi http status) và các thông số tùy chỉnh như timeout (5-10 giây), số lần gửi lại (1-5 lần), khoảng chờ (2-3600 giây).
Kiểu chứng thực Webhooks: Chọn phương thức bảo mật đính kèm vào header khi Tingee gửi webhook (None, API Key, hoặc API Credentials). 
Đối tác có thể kích hoạt/vô hiệu hóa (bật/tắt) hoặc chỉnh sửa cấu hình Webhook trực tiếp từ màn hình quản lý.

Nhật ký Webhook
Đối tác có thể xem lịch sử gửi Webhook (Trạng thái webhook, số lần gửi lại, HTTP status code...) của từng endpoint trực tiếp tại trang Sử dụng (Usage), tab Lịch sử webhook của Portal. 
Tại đây, Đối tác có thể theo dõi chi tiết trạng thái delivery, số lần retry, HTTP response status code, thời gian phản hồi, hoặc bấm Xem chi tiết để xem payload Request/Response cụ thể của từng sự kiện webhook.

Hỗ trợ liên kết Số tài khoản gốc
Khi gọi API Tạo tài khoản ảo (VA), đối tác sử dụng tham số isNotifyAccountNumber:

false (mặc định): Tạo tài khoản ảo (Virtual Account - VA).
true: Liên kết số tài khoản ngân hàng gốc để nhận biến động số dư.
Chỉ các ngân hàng và loại tài khoản trong bảng dưới đây hỗ trợ liên kết số tài khoản gốc:

VPBank	Cá nhân, Doanh nghiệp	✓	Chưa hỗ trợ STK gốc cho HKD

Các ngân hàng khác
Đối với các ngân hàng còn lại, hệ thống mặc định hỗ trợ tạo tài khoản ảo (VA), đối tác truyền isNotifyAccountNumber = false hoặc để mặc định.

Quy tắc phát sinh Webhook: Chuyển tiền vào STK gốc vs Số tài khoản ảo (VA)
Tài khoản hỗ trợ liên kết STK gốc (isNotifyAccountNumber = true): Khi người chuyển tiền chuyển vào Số tài khoản gốc, ngân hàng mới ghi nhận biến động và gửi dữ liệu về Tingee → Tingee phát sinh Webhook gửi sang đối tác.
Tài khoản KHÔNG hỗ trợ liên kết STK gốc (chỉ hỗ trợ VA, isNotifyAccountNumber = false):
Bắt buộc người chuyển tiền phải chuyển vào Số tài khoản ảo (VA) được cấp thì Tingee mới nhận được thông báo biến động và gửi Webhook.
Nếu chuyển tiền vào Số tài khoản gốc, phía ngân hàng sẽ không ghi nhận giao dịch thuộc phạm vi tích hợp của Tingee → Tingee không nhận được giao dịch từ ngân hàng → Không có Webhook gửi sang đối tác.

Trước khi bắt đầu
Base URL: https://uat-open-api.tingee.vn (UAT) · https://open-api.tingee.vn (PROD)
Xác thực: Mọi request cần gửi kèm các header x-client-id, x-request-timestamp và chữ ký x-signature (HMAC SHA512). Xem Hướng dẫn lấy API Key & sinh chữ ký.

Khởi tạo Virtual Account

2
Xác thực OTP

3
Đăng ký nhận biến động (một số ngân hàng)
Với các ngân hàng yêu cầu đăng ký riêng như ACB, gọi register-notify rồi xác thực OTP qua confirm-register-notify.

4
Nhận Webhook & Đối soát
Nhận thông báo giao dịch qua Webhook và dùng API transaction/get-paging để đối soát định kỳ.

API này dùng để tạo mới tài khoản ảo (Virtual Account - VA) cho Merchant, cho phép nhận thông báo biến động số dư và quản lý dòng tiền tách biệt.

Các ngân hàng hỗ trợ liên kết STK gốc:
ACB, TPBank: Hỗ trợ mọi loại tài khoản (Cá nhân, HKD, Doanh nghiệp). (Lưu ý: TPBank chỉ Doanh nghiệp mới có VA, Cá nhân và HKD không có VA).
VPBank: Hỗ trợ tài khoản Doanh nghiệp và Cá nhân.
OCB: Hỗ trợ tài khoản Doanh nghiệp và Hộ kinh doanh.
VietinBank: Hỗ trợ tài khoản Cá nhân và Hộ kinh doanh.
PGBank, Co-opBank: Chỉ hỗ trợ liên kết STK gốc (không có VA, hệ thống tự động xử lý).
Cơ chế nhận Webhook giao dịch theo loại tài khoản:
Với tài khoản liên kết STK gốc (isNotifyAccountNumber = true): Chuyển tiền vào STK gốc mới phát sinh Webhook từ Tingee.
Với tài khoản không hỗ trợ liên kết gốc (chỉ hỗ trợ VA, isNotifyAccountNumber = false): Bắt buộc chuyển tiền vào số tài khoản ảo (VA). Nếu chuyển vào STK gốc, phía ngân hàng sẽ không gửi giao dịch về Tingee → Tingee không nhận được GD từ bank → Không có Webhook.
Đối với các ngân hàng còn lại, hệ thống mặc định chỉ hỗ trợ tạo tài khoản ảo (VA), vui lòng để isNotifyAccountNumber = false hoặc không truyền.

API này dùng để đăng ký nhận thông báo giao dịch ghi nợ (tiền ra) trên số tài khoản gốc ACB. Sau khi đăng ký thành công, mỗi khi tài khoản phát sinh giao dịch trừ tiền, TINGEE sẽ gửi Webhook về hệ thống của đối tác.

Phạm vi áp dụng
Chỉ hỗ trợ ngân hàng ACB (bankBin = "970416"), áp dụng cho tài khoản Cá nhân, Hộ kinh doanh và Doanh nghiệp.
API đăng ký trên số tài khoản gốc, không tạo tài khoản ảo (VA).
Nếu số tài khoản đã đăng ký nhận biến động ghi có (tạo bằng Tạo/Liên kết số tài khoản với isNotifyAccountNumber = true), hệ thống sẽ chuyển đăng ký sang nhận cả ghi có và ghi nợ.

Kết quả: API luôn trả về HTTP 200, kiểm tra trường code (00 = thành công). Xem Danh sách mã lỗi.
Sau khi khách hàng thực hiện liên kết ngân hàng thành công thông qua SDK, tài khoản ngân hàng liên kết đó sẽ được tự động liên kết với Shop của Merchant và hỗ trợ cho các luồng thanh toán hoặc đối soát sau này.

Luồng Hoạt Động (Integration Flow)
Khởi tạo Session: Hệ thống máy chủ (Backend) của đối tác gọi OpenAPI Tạo phiên liên kết để nhận về một SDK URL (có chứa token và chữ ký s bảo mật).
Nhúng và Gọi SDK: Đối tác nhúng thư viện tingee-bank-link.js và gọi hàm mở SDK dưới dạng Popup (Modal) hoặc Inline Container.
Thực hiện Liên kết: Khách hàng chọn ngân hàng và hoàn tất các bước liên kết an toàn trên giao diện của Tingee.
Nhận kết quả:
Callback: SDK truyền kết quả liên kết ngân hàng (thành công, thất bại, hủy bỏ) trực tiếp về ứng dụng client của bạn qua callback.
Redirect: Nếu session có cấu hình redirectUrl, khách hàng sẽ được điều hướng về lại URL của đối tác kèm các thông tin kết quả gắn trên query parameters.
Webhook: Đồng thời, hệ thống Tingee sẽ gửi một thông báo Webhook liên kết ngân hàng về máy chủ của bạn để đồng bộ trạng thái tài khoản liên kết theo thời gian thực (real-time).

Tạo một phiên liên kết tài khoản ngân hàng để lấy URL SDK hiển thị ở client.

1. Request Headers
Header	Kiểu	Bắt buộc	Mô tả
Content-Type	string	✓	Định dạng dữ liệu. Bắt buộc: application/json
x-client-id	string	✓	Client ID được Tingee cấp cho đối tác.
x-request-timestamp	string	✓	Thời gian gửi request (format: yyyyMMddHHmmssSSS, ví dụ: 20260701153045999).
x-signature	string	✓	Chữ ký HMAC-SHA512 xác thực tính toàn vẹn của dữ liệu request. Chi tiết xem tại Cách sinh chữ ký.
2. Request Body (JSON)
Thuộc tính	Kiểu dữ liệu	Bắt buộc	Mô tả
type	string	✕	Loại session. Giá trị: bank-link hoặc bank-config. Mặc định của đối tác là bank-link. Nếu cần mở màn cấu hình, truyền bank-config.
shopId	number	✕	ID cửa hàng cần liên kết tài khoản ngân hàng sau khi hoàn tất.
allowedBanks	array[string]	✕	Danh sách mã ngân hàng được hiển thị trong SDK (ví dụ: ["BIDV", "VCB", "ACB"]). Nếu không truyền, hệ thống hiển thị toàn bộ ngân hàng được hỗ trợ.
Giá trị là mã ngân hàng (code trong Danh sách ngân hàng hỗ trợ), không phải mã BIN.
disallowedBanks	array[string]	✕	Danh sách mã ngân hàng cần ẩn khỏi SDK (ví dụ: ["TPB"]). Sau khi loại trừ, phải còn ít nhất một ngân hàng khả dụng.
bankName	string	✕	Chỉ định mã một ngân hàng duy nhất (ví dụ BIDV) để tự động khóa luồng và chuyển khách hàng vào thẳng giao diện liên kết của ngân hàng đó.
bankAccountType	string	✕	Chỉ định loại tài khoản liên kết: personal-account (Cá nhân), business-account (Doanh nghiệp), business-household-account (Hộ kinh doanh).
redirectUrl	string	✕	URL của bạn để chuyển tiếp trình duyệt của khách hàng sau khi hoàn tất liên kết trên SDK di động hoặc web.
metadata	string	✕	Dữ liệu tùy chỉnh của đối tác (tối đa 1000 ký tự). Giá trị này được gửi kèm trong Webhook liên kết tài khoản.
isEnableQRScan	boolean	✕	Bật nút quét mã QR trên giao diện SDK di động để tự điền thông tin tài khoản từ mã QR ngân hàng. Mặc định không bật.
Chỉ hiển thị với một số ngân hàng / loại tài khoản được SDK hỗ trợ.
merchantId	number	~	ID Merchant con. Bắt buộc khi sử dụng tài khoản Master Merchant để tạo session cho một Merchant con; Merchant con phải thuộc Master Merchant đang gọi API.
Ví dụ Request Body:
{
  "shopId": 123,
  "type": "bank-link",
  "allowedBanks": ["BIDV", "VCB", "ACB"],
  "redirectUrl": "https://merchant.example.vn/bank-link/callback"
}

3. Response Dữ Liệu
Tingee OpenAPI sẽ trả về kết quả dưới dạng JSON:

Thuộc tính	Kiểu dữ liệu	Mô tả

message	string	Thông báo mô tả trạng thái phản hồi.
data	string	Đường dẫn URL SDK liên kết ngân hàng hoàn chỉnh chứa token bảo mật.
Ví dụ Response Thành công:
{
  "code": "00",
  "message": "Success",
  "data": "https://uat-bank-link.tingee.vn?token=eyJtZXJjaGFudElkIjoxMDAxfQ&s=7d5b6e..."
}

Ví dụ Response Lỗi:
{
  "code": "97",
  "message": "Invalid signature",
  "data": null
}

Danh sách mã lỗi nghiệp vụ:
Mã lỗi	Ý nghĩa	Hướng xử lý
1063	Không còn ngân hàng nào khả dụng	Kiểm tra allowedBanks chứa ít nhất một ngân hàng được hỗ trợ.
1031	Không tìm thấy cửa hàng	Kiểm tra shopId tồn tại và thuộc đúng Merchant, hoặc bỏ trống shopId.
1094	Cửa hàng không thuộc Master Merchant	Kiểm tra shopId đã được gán cho Master Merchant, hoặc bỏ trống shopId.

Others	Lỗi khác	Xem Danh sách mã lỗi.
4. Ví dụ Backend (Node.js)
Dưới đây là mã nguồn minh họa cách gọi API tạo session liên kết từ máy chủ của bạn:

// timestamp và signature được sinh theo hướng dẫn tại mục "Bắt đầu ngay"
export async function createBankLinkSession(timestamp, signature) {
  const body = {
    shopId: 123,
    type: 'bank-link',
    redirectUrl: 'https://merchant.example.vn/bank-link/callback'
  };

  const response = await fetch(`${process.env.TINGEE_OPEN_API_URL}/v1/create-bank-link-session`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'x-client-id': process.env.TINGEE_CLIENT_ID,
      'x-request-timestamp': timestamp,
      'x-signature': signature
    },
    body: JSON.stringify(body)
  });

  const result = await response.json();
  if (result.code !== '00') {
    throw new Error(`[${result.code}] ${result.message}`);
  }

  // data chính là URL SDK hoàn chỉnh dùng ở Client
  return {
    url: result.data
  };
}

Tingee cung cấp thư viện Web SDK (Frontend) giúp bạn nhúng trực tiếp giao diện liên kết ngân hàng vào website dưới dạng Popup (Modal) hoặc hiển thị Inline trực tiếp trên trang.

1. Nhúng thư viện SDK
Thêm thẻ <script> sau vào mã nguồn HTML trang web của bạn (ví dụ: index.html hoặc tệp template chính):

<script src="https://uat-bank-link.tingee.vn/js/tingee-bank-link.js"></script>

Môi trường Production:

<script src="https://bank-link.tingee.vn/js/tingee-bank-link.js"></script>

2. Cấu hình & Lắng nghe sự kiện (Setup)
Trước khi mở màn hình liên kết ngân hàng, bạn nên đăng ký các sự kiện callback lắng nghe kết quả bằng hàm TingeeBankLink.Setup(config).

TingeeBankLink.Setup({
  // Kích thước mặc định của cửa sổ Popup
  size: 'large', 

  // Tùy chỉnh màu sắc chủ đạo
  theme: {
    primaryColor: '#1E88E5'
  },
  
  // Sự kiện: Liên kết tài khoản ngân hàng thành công
  onSuccess: function(data) {
    console.log("Liên kết thành công!", data);
    // Ví dụ: làm mới danh sách tài khoản hoặc thông báo thành công
  },
  
  // Sự kiện: Liên kết thất bại (ví dụ: lỗi nghiệp vụ từ ngân hàng)
  onFailed: function(data) {
    console.error("Liên kết thất bại:", data.errorMessage);
  },
  
  // Sự kiện: Người dùng chủ động hủy liên kết (ví dụ: nhấn nút X đóng popup)
  onCancelled: function(data) {
    console.log("Người dùng hủy liên kết:", data);
  },
  
  // Sự kiện: Có lỗi hệ thống phát sinh trong SDK
  onError: function(data) {
    console.error("Lỗi hệ thống SDK:", data);
  },
  
  // Sự kiện: Popup đóng lại (chạy sau các callback thành công/thất bại/hủy)
  onClose: function() {
    console.log("Cửa sổ SDK đã đóng.");
  }
});

3. Hiển thị Giao diện Liên kết
Sau khi gọi Backend của bạn và nhận được url (SDK URL từ OpenAPI), bạn gọi hàm TingeeBankLink.Url.Open(url, options) để kích hoạt giao diện SDK.

// url nhận được từ backend của bạn thông qua OpenAPI v1/create-bank-link-session
const bankLinkUrl = "https://uat-bank-link.tingee.vn?token=...";

// Mở SDK
TingeeBankLink.Url.Open(bankLinkUrl);

[!TIP] Bạn có thể truyền các sự kiện callback và các cấu hình kích thước đè lên cấu hình toàn cục (Global Setup) ngay trong tham số thứ 2 của hàm Open nếu cần tùy chỉnh riêng cho từng phiên.

import React, { useEffect } from 'react';

// Khai báo kiểu TypeScript toàn cục tránh báo lỗi compiler
declare global {
  interface Window {
    TingeeBankLink: any;
  }
}

export default function BankLinkButton() {
  useEffect(() => {
    if (window.TingeeBankLink) {
      window.TingeeBankLink.Setup({
        size: 'large',
        onSuccess: (data: any) => {
          console.log("Liên kết thành công", data);
          // Thực hiện cập nhật UI hoặc gọi API tải lại dữ liệu tài khoản
        },
        onCancelled: () => console.log("Khách hàng đóng SDK"),
      });
    }
  }, []);

  const handleOpenSDK = async () => {
    try {
      // Gọi API nội bộ của bạn để sinh link liên kết ngân hàng
      const response = await fetch('/api/bank-link/session', { method: 'POST' });
      const { url } = await response.json();
      
      if (window.TingeeBankLink) {
        window.TingeeBankLink.Url.Open(url);
      } else {
        alert("SDK chưa được tải thành công!");
      }
    } catch (error) {

    }

  return (

    </button>
  );

7. Xử lý qua Redirect URL
Nếu bạn đã cung cấp tham số redirectUrl khi tạo session ở Backend, SDK sẽ tự động điều hướng toàn bộ trình duyệt web của khách hàng về địa chỉ đó kèm các thông số kết quả dưới dạng query parameters:

https://merchant.example.vn/bank-link/callback?status=success&bankName=BIDV&merchantAccountNumberId=456&shopId=123


Đối tác có thể đọc thông tin trên URL callback này để hiển thị thông báo kết quả tương ứng.

8. Đồng bộ kết quả qua Webhook (Khuyến nghị)
Mặc dù SDK và Redirect URL cung cấp phản hồi lập tức trên giao diện người dùng (Client-side), việc sử dụng Webhook (Server-side) là giải pháp an toàn và tin cậy nhất để đồng bộ trạng thái liên kết tài khoản ngân hàng về hệ thống của bạn.

Hệ thống Tingee sẽ tự động gửi một POST request chứa thông tin tài khoản ngân hàng liên kết thành công ngay sau khi sự kiện diễn ra.

Chi tiết về cấu hình, định dạng dữ liệu (payload) và cách xác thực chữ ký bảo mật vui lòng xem tại tài liệu Webhook liên kết ngân hàng.

Để cổng thanh toán hoạt động chính xác và mang đậm dấu ấn thương hiệu của doanh nghiệp, bạn cần thực hiện cấu hình các thông số cơ bản trên Tingee Merchant Portal.

1. Truy cập trang cấu hình
Truy cập vào trang Nhà phát triển trên Tingee Merchant Portal (yêu cầu đăng nhập).
Chọn tab Cấu hình thanh toán (Payment Gateway).
Truy cập trang cấu hình

2. Các thông số cần cấu hình
Tại đây, bạn cần thiết lập các thông số sau để cổng thanh toán có thể hoạt động:

Các thông số cấu hình

2.1. Logo Cổng thanh toán
Mô tả: Tải lên hình ảnh Logo của doanh nghiệp bạn. Logo này sẽ được hiển thị nổi bật trên giao diện thanh toán.
Quy định: Hỗ trợ định dạng JPG, PNG, kích thước tối đa 2MB. Tỷ lệ khuyến nghị là 1:1.
2.2. Tên thương hiệu hiển thị (*)
Mô tả: Tên doanh nghiệp hoặc cửa hàng sẽ được hiển thị trên cổng thanh toán giúp khách hàng nhận diện.
Bắt buộc: Có.
2.3. Đường dẫn IPN (*)
Mô tả: Đường dẫn (URL) máy chủ của bạn để Tingee gửi thông báo trạng thái giao dịch (Webhook).
Hoạt động: Hệ thống Tingee sẽ gửi dữ liệu đơn hàng (qua HTTP POST) về địa chỉ này mỗi khi có sự thay đổi trạng thái (Thành công, Hết hạn, Hủy). Đặc biệt, với giao dịch QR Tĩnh, nếu khách hàng chuyển khoản sau khi đơn hàng đã hết hạn/bị hủy, hệ thống vẫn sẽ đẩy Webhook ghi nhận trạng thái thực tế (Hết hạn-Thành công, Hủy-Thành công) hoặc các giao dịch chuyển đúp (Duplicate).
Bắt buộc: Có.
Lưu ý: URL phải là public và có thể truy cập được từ Internet (không dùng localhost). Trong quá trình phát triển, bạn có thể sử dụng các công cụ như webhook.site để giả lập nhận Webhook test.
2.4. Đường dẫn trả về (Return URL)
Mô tả: URL (hoặc App Scheme) điều hướng khách hàng về lại web/app của bạn sau khi thanh toán xong.
Bắt buộc: Không (nếu có truyền returnUrl qua API Tạo link thanh toán thì hệ thống sẽ ưu tiên tham số truyền từ API).
2.5. Các Tài khoản cho phép thanh toán (*)
Mô tả: Chọn các tài khoản sẽ hiển thị khi khách hàng thanh toán trên cổng.
Bắt buộc: Có.
Lưu ý quan trọng: Nên chọn Tài khoản ngân hàng có hỗ trợ QR Động (VietQR / Mã hóa linh hoạt). Nếu dùng QR Tĩnh, hệ thống sẽ phải quét theo nội dung chuyển khoản thủ công, rất dễ dẫn đến việc bị rớt đơn hàng do khách hàng nhập sai cú pháp.
3. Lưu cấu hình

Tạo một đường dẫn thanh toán (Checkout URL) để gửi cho khách hàng.

1. Request Headers
Header	Type	Bắt buộc	Mô tả

x-signature	string	✓	Chữ ký xác thực request để đảm bảo tính toàn vẹn dữ liệu.

requestId	string	✓	Mã request định danh.
(Max: 36 char, chuẩn UUID v4)
orderId	string	✓	Mã đơn hàng trên hệ thống của bạn.
(Max: 100 char, chỉ chứa chữ, số, -, _)
amount	number	✓	Số tiền cần thanh toán.
(Min: 2,000, Max: 10,000,000,000)
merchantId	number	✕	Mã Merchant.

currency	string	✕	Đơn vị tiền tệ. Mặc định là VND.
(Max: 10 char)
expireInMinute	number	✕	Thời gian hết hạn của link tính bằng phút. Mặc định là 30.
(Min: 5, Max: 30)
description	string	✕	Mô tả ngắn gọn về giao dịch hiển thị trên cổng thanh toán.
(Max: 200 char)
orderInfo	string	✕	Thông tin bổ sung nội bộ về đơn hàng.
(Max: 1000 char)
customerEmail	string	✕	Email khách hàng.
vaAccountNumber	string	✕	Số tài khoản ảo (Virtual Account) nếu bạn muốn chỉ định nhận đích danh.
(Max: 50 char)
returnUrl	string	✕	URL (hoặc App Scheme) điều hướng khách hàng về lại web/app của bạn sau khi thanh toán xong.
(Max: 500 char, chuẩn URL)

Bên cạnh việc chuyển hướng (redirect) người dùng trực tiếp đến Checkout URL, Tingee cung cấp Frontend SDK giúp bạn nhúng trải nghiệm thanh toán vào thẳng website của mình dưới dạng Popup (Modal). Điều này giúp giữ chân khách hàng ở lại trang web của bạn và tối ưu hóa tỷ lệ chuyển đổi.

1. Cài đặt SDK
Tích hợp SDK thông qua thẻ <script> nhúng vào HTML (ví dụ: index.html của React/Vue/Angular). Tùy thuộc vào môi trường bạn đang phát triển (UAT hay PROD), hãy sử dụng đường dẫn tương ứng:

2. Cấu hình Toàn cục (Global Setup)
Để ứng dụng của bạn hoạt động mượt mà, bạn nên cấu hình SDK một lần duy nhất ngay khi ứng dụng vừa khởi động.

Sử dụng hàm Tingee.Setup(config) để định nghĩa các sự kiện lắng nghe (callbacks) dùng chung cho toàn bộ website.

// Khởi tạo ngay từ đầu (ví dụ: trong file index.js, main.ts, hoặc App.tsx)
window.Tingee.Setup({
  // Cấu hình hiển thị (tùy chọn)
  size: 'medium', // 'small' | 'medium' | 'large' (mặc định 'medium')
  
  // Giao dịch thành công
  onSuccess: function(data) {
    console.log("Thanh toán thành công!", data);
    window.location.href = "/checkout/success";
  },
  
  // Giao dịch thất bại / hết hạn
  onFailed: function(error) {
    console.error("Giao dịch thất bại hoặc hết hạn", error);
  },
  
  // Người dùng chủ động hủy (nhấn nút X)
  onCancelled: function() {
    console.log("Người dùng đã hủy thanh toán.");
  },
  
  // Cửa sổ thanh toán đóng lại (dù thành công hay thất bại)
  onClose: function() {
    console.log("Popup thanh toán đã được đóng.");
  }
});

3. Mở Cửa sổ Thanh toán
Sau khi hệ thống Backend của bạn gọi API Tạo link thanh toán và trả về Checkout URL, bạn chỉ cần gọi hàm Tingee.Url.Open() để hiển thị popup.

// checkoutUrl lấy từ API backend (ví dụ: https://pay.tingee.vn/checkout?token=xxx&s=yyy)
const checkoutUrl = "https://pay.tingee.vn/checkout?...";

// Hiển thị Popup
window.Tingee.Url.Open(checkoutUrl);

(Bạn cũng có thể truyền thêm object cấu hình vào tham số thứ 2 của hàm Open nếu muốn ghi đè cấu hình global cho riêng giao dịch này).

4. Ví dụ Tích hợp Framework
Dưới đây là ví dụ cách khởi tạo (Global Setup) và gọi hàm hiển thị (Open) đối với các Frontend Framework phổ biến:

React
Angular
Vue 3
App.tsx
import React, { useEffect } from 'react';

// Nếu dùng TypeScript, có thể cần khai báo global để tránh báo lỗi
// declare global { interface Window { Tingee: any; } }

export default function App() {
  // 1. Cấu hình Global khi ứng dụng khởi chạy
  useEffect(() => {
    // Đảm bảo script ở index.html đã load xong
    if (window.Tingee) {
      window.Tingee.Setup({
        size: 'medium',
        onSuccess: (data: any) => {
          console.log("Thanh toán thành công", data);
          // Điều hướng React Router
          // navigate('/success');
        },
        onCancelled: () => console.log("Khách hàng hủy"),
      });
    }
  }, []);

  // 2. Hàm xử lý nút thanh toán
  const handlePayment = async () => {
    try {
      // Giả lập gọi API nội bộ lấy Checkout URL
      const response = await fetch('/api/create-payment');
      const { checkoutUrl } = await response.json();
      
      // Mở Popup
      if (window.Tingee) {
        window.Tingee.Url.Open(checkoutUrl);
      } else {
        alert("Không tìm thấy SDK Tingee!");
      }
    } catch (error) {
      console.error("Lỗi tạo thanh toán", error);
    }
  };

  return (
    <div>
      <h1>Giỏ hàng</h1>
      <button onClick={handlePayment}>Thanh toán ngay</button>
    </div>
  );
}

import UIKit
import TingeePaySDK

class CheckoutViewController: UIViewController {

    func openPayment(checkoutUrlString: String) {
        guard let checkoutUrl = URL(string: checkoutUrlString) else { return }
        
        // Gọi SDK để hiển thị cổng thanh toán
        TingeePay.presentCheckout(

            checkoutUrl: checkoutUrl, 
            style: .bottomSheet, // Hoặc .fullScreen
            delegate: self
        )
    }
}

4. Lắng nghe & Xử lý kết quả
Để nhận các sự kiện từ màn hình thanh toán, bạn cần tuân thủ và kế thừa protocol TingeePayCheckoutDelegate:

extension CheckoutViewController: TingeePayCheckoutDelegate {
    
    /// Sự kiện: Thanh toán hoàn tất hoặc kết thúc (Thành công, Lỗi, Hết hạn...)
    func tingeePayCheckoutDidFinish(with result: TingeePaymentResult) {
        print("Trạng thái thanh toán: \(result.status.rawValue)")
        print("Mã đơn hàng: \(result.orderId ?? "")")
        
        switch result.status {
        case .success:
            // Xử lý khi thanh toán thành công (ví dụ: Chuyển màn hình cảm ơn)
            print("Thanh toán thành công!")
            
        case .failed:
            // Giao dịch thanh toán thất bại
            print("Lỗi thanh toán: \(result.errorMessage ?? "")")
            
        case .cancelled:
            // Giao dịch bị hủy bỏ trên cổng
            print("Giao dịch đã bị huỷ.")
            
        case .expired:
            // Hết hạn thời gian thanh toán
            print("Đơn hàng đã hết hạn thanh toán.")
            
        case .error:
            // Lỗi hệ thống phát sinh
            print("Lỗi hệ thống cổng thanh toán.")
        }
    }
    
    /// Sự kiện: Người dùng chủ động nhấn nút "Đóng" (X) hoặc vuốt tắt Bottom Sheet để thoát
    func tingeePayCheckoutDidCancel() {
        print("Người dùng đã thoát màn hình thanh toán.")
    }
    
    /// Sự kiện: Lỗi phát sinh khi SDK cố gắng tải cổng thanh toán (ví dụ: Sai định dạng URL, Mất kết nối Internet...)
    func tingeePayCheckoutDidFail(with error: Error) {
        print("Lỗi khởi tạo/tải màn hình thanh toán: \(error.localizedDescription)")
    }
}


5. Mô hình dữ liệu

3. Khởi động màn hình thanh toán
Cổng thanh toán cung cấp hai phương thức hiển thị chính: Toàn màn hình (FullScreen) hoặc Nửa màn hình (Bottom Sheet).

Trước khi mở SDK, bạn cần lấy paymentUrl từ hệ thống máy chủ (Backend) của bạn (qua API Tạo link thanh toán) và chuẩn bị returnUrl đã đăng ký.

3.1. Gọi từ Activity (Khuyên dùng)
Sử dụng ActivityResultLauncher để khởi động màn hình thanh toán và nhận kết quả trả về một cách hiện đại.

Bước 1: Đăng ký Launcher trong Activity của bạn
private val paymentResultLauncher = registerForActivityResult(
    ActivityResultContracts.StartActivityForResult()
) { result ->
    if (result.resultCode == Activity.RESULT_OK) {
        val data = result.data
        val status         = data?.getStringExtra("EXTRA_PAYMENT_STATUS")
        val orderId        = data?.getStringExtra("EXTRA_ORDER_ID")
        val transactionCode = data?.getStringExtra("EXTRA_TRANSACTION_CODE")
        val errorCode      = data?.getStringExtra("EXTRA_ERROR_CODE")
        val errorMessage   = data?.getStringExtra("EXTRA_ERROR_MESSAGE")
        val rawJson        = data?.getStringExtra("EXTRA_PAYMENT_DATA_JSON")

        when (status) {
            "success"   -> { /* Thanh toán thành công */ }
            "failed"    -> { /* Thanh toán thất bại */ }
            "cancelled" -> { /* Người dùng đã hủy giao dịch trên cổng */ }
            "expired"   -> { /* Mã thanh toán hết hạn */ }
            "error"     -> { /* Lỗi hệ thống phát sinh */ }
        }
    } else {
        // Người dùng đóng màn hình SDK (bằng cử chỉ vuốt, nút quay lại vật lý) mà không có kết quả
    }
}

Bước 2: Mở cổng thanh toán khi có URL
val intent = TingeePaySDK.createIntent(
    context      = this,
    paymentUrl   = paymentUrl,   // URL thanh toán lấy từ API Backend của bạn
    returnUrl    = returnUrl,    // URL/Deep link trả về đã khai báo
    isEmbedded   = true,         // true: Ẩn các phần header/footer không cần thiết của web (khuyên dùng)
    immediateResult = true,      // true: Bắn kết quả trả về ngay khi hoàn tất
    primaryColor = "#1E88E5",    // Màu sắc thương hiệu dạng Hex (null = sử dụng mặc định)
    isFullScreen = true          // true: Toàn màn hình | false: Hiển thị Bottom Sheet (nửa màn hình)
)
paymentResultLauncher.launch(intent)

3.2. Gọi từ Fragment
Khi mở SDK từ một Fragment, bạn cần lưu ý hai điểm quan trọng sau:

registerForActivityResult bắt buộc phải được khai báo dưới dạng thuộc tính (Property) ở cấp lớp của Fragment. Không được khai báo bên trong các hàm callback như onViewCreated(), onStart(), hoặc trong các sự kiện click listener (vi phạm sẽ gây lỗi IllegalStateException khi chạy ứng dụng).
Sử dụng hàm requireContext() thay thế cho this khi truyền tham số ngữ cảnh.
CheckoutFragment.kt
class CheckoutFragment : Fragment() {

    // ✅ Khai báo Launcher như một Property ở cấp lớp
    private val paymentResultLauncher = registerForActivityResult(
        ActivityResultContracts.StartActivityForResult()
    ) { result ->
        if (result.resultCode == Activity.RESULT_OK) {
            val status = result.data?.getStringExtra("EXTRA_PAYMENT_STATUS")
            val orderId = result.data?.getStringExtra("EXTRA_ORDER_ID")
            // Xử lý logic kết quả...
        }
    }

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        btnPay.setOnClickListener {
            // ✅ Khởi tạo Intent và kích hoạt Launcher từ sự kiện click
            val intent = TingeePaySDK.createIntent(
                context         = requireContext(), // Dùng requireContext()
                paymentUrl      = paymentUrl,
                returnUrl       = returnUrl,
                isEmbedded      = true,
                immediateResult = true,
                primaryColor    = "#1E88E5",
                isFullScreen    = false // Ví dụ: mở dạng Bottom Sheet
            )
            paymentResultLauncher.launch(intent)
        }
    }
}

4. Mô tả các tham số cấu hình
Hàm TingeePaySDK.createIntent hỗ trợ các tham số cấu hình linh hoạt:

Tham số	Kiểu dữ liệu	Mặc định	Mô tả
context	Context	—	Ngữ cảnh của Activity/Fragment đang gọi.
paymentUrl	String	—	Bắt buộc. Đường dẫn thanh toán được tạo từ API Backend.
returnUrl	String?	null	URL hoặc deep link để chuyển hướng ứng dụng sau khi hoàn thành.
isEmbedded	Boolean	true	Nếu đặt là true, SDK sẽ ẩn thanh header và footer mặc định của web cổng thanh toán để tạo cảm giác native.
immediateResult	Boolean	true	true để gửi kết quả ngay lập tức khi hệ thống cổng thanh toán hoàn thành xử lý.
primaryColor	String?	null	Màu sắc chủ đạo của giao diện thanh toán dạng chuỗi Hex (ví dụ: "#E53935"). Nếu null, hệ thống sử dụng màu mặc định của cổng.
isFullScreen	Boolean	true	Cấu hình chế độ hiển thị:
- true: Hiển thị toàn màn hình.
- false: Hiển thị dạng Bottom Sheet (chiếm khoảng 50% chiều cao màn hình, hỗ trợ kéo xuống để đóng).

7. Các lưu ý quan trọng khi tích hợp
Quy trình tạo link: SDK di động không trực tiếp xử lý việc gọi API tạo đường dẫn thanh toán. Ứng dụng tích hợp có nhiệm vụ gọi về Backend của mình để nhận paymentUrl trước khi chuyển tiếp cho SDK.
Tự động Deeplink: Khi người dùng chọn hình thức thanh toán bằng ứng dụng ngân hàng, SDK sẽ tự động phát hiện và mở ứng dụng ngân hàng tương thích đã cài trên thiết bị. Trong trường hợp thiết bị chưa cài đặt ứng dụng ngân hàng đó, SDK sẽ hiển thị thông báo popup thân thiện để người dùng thử lại hoặc chọn cách thanh toán khác.
Bộ nhớ: SDK tự động giải phóng tài nguyên và dọn dẹp bộ nhớ đệm WebView khi đóng màn hình thanh toán để tránh gây rò rỉ bộ nhớ (memory leak).

QR tĩnh là mã được tạo một lần và sử dụng nhiều lần. Mặc dù chuẩn VietQR cho phép gắn sẵn số tiền và nội dung, nhưng thực tế triển khai cần lưu ý:

Hành vi người dùng: Một số ngân hàng (như MBBank) vẫn cho phép khách hàng tự sửa đổi số tiền hoặc nội dung trước khi bấm chuyển tiền.

QR động
Mỗi giao dịch sẽ sinh ra một mã QR duy nhất kèm theo mã định danh (billId/orderId).

Tính chính xác: QR động thường khóa thông tin số tiền. Ngay cả khi ngân hàng cho phép sửa nội dung, hệ thống vẫn nhận diện đúng đơn hàng nhờ mã định danh đính kèm trong dữ liệu ngân hàng trả về.
Hiệu lực: Có thể cấu hình thời gian hết hạn, đảm bảo mã không còn giá trị sau khi thanh toán hoặc quá thời gian quy định.
Ứng dụng: Tối ưu cho Thương mại điện tử, Máy bán hàng tự động, hoặc Hệ thống quản lý bán hàng (POS).

API này dùng để tạo mã QR tĩnh (VietQR) cho tài khoản ngân hàng cố định. Loại QR này phù hợp với các điểm thanh toán cố định hoặc các mô hình không yêu cầu theo dõi trạng thái thanh toán tự động cho từng đơn hàng.

POST
https://open-api.tingee.vn/v1/generate-viet-qr
PROD
UAT

API khởi tạo mã QR tĩnh theo tiêu chuẩn VietQR. Khách hàng có thể quét mã này để chuyển khoản thủ công vào tài khoản của bạn.

Header Request
Header	Bắt buộc	Mô tả
Content-Type	✓	application/json
x-client-id	✓	Mã định danh của đối tác do TINGEE cung cấp.
x-signature	✓	Chữ ký xác thực HMAC SHA512. Xem thêm tại Cách sinh chữ ký.
x-request-timestamp	✓	Thời gian gửi request (format: yyyyMMddHHmmssSSS, múi giờ UTC+7)
Body Parameter
Trường	Kiểu	Bắt buộc	Mô tả
bankBin	string	✓	Mã BIN ngân hàng. Xem tại Danh sách ngân hàng hỗ trợ.
accountNumber	string	✓	Số tài khoản nhận tiền (STK gốc hoặc số tài khoản ảo).
Với bankBin = BAOKIM, phải là số tài khoản ảo Bảo Kim đã liên kết trên TINGEE.
amount	number	✕	Số tiền mặc định (VND, hiển thị khi quét). Bỏ trống để người chuyển tự nhập số tiền.
content	string	✕	Nội dung chuyển khoản mặc định.
Ví dụ mã nguồn
cURL
NestJS
C#
Java
PHP
curl --location --request POST 'https://open-api.tingee.vn/v1/generate-viet-qr' \
--header 'accept: application/json' \
--header 'x-client-id: YOUR_CLIENT_ID' \
--header 'x-request-timestamp: 20240509154004003' \
--header 'x-signature: YOUR_SIGNATURE' \
--header 'Content-Type: application/json' \
--data '{
  "bankBin": "970418",
  "accountNumber": "21510002865945",
  "amount": 100000,
  "content": "Thanh toan don hang"
}'

Response mẫu
{
  "code": "00",
  "message": "Success",
  "data": {
    "qrCode": "00020101021238540010A0000007270124000697041801102151000286...",
    "qrCodeImage": "data:image/png;base64,iVBORw0KGgoAAAANSU..."
  }
}

Trường	Kiểu	Mô tả
code	string	Mã kết quả (00 = Thành công).
message	string	Thông điệp phản hồi.
data.qrCode	string	Chuỗi nội dung mã QR theo chuẩn VietQR (EMVCo).
data.qrCodeImage	string	Ảnh QR định dạng PNG, dạng Data URL Base64 (data:image/png;base64,...), có thể gán trực tiếp vào thuộc tính src của thẻ <img>.

Code	Mô tả	Hướng xử lý

90, 91, 92, 97	Lỗi xác thực request (timestamp, client-id, chữ ký)	Xem Mã lỗi hệ thống.
Others	Lỗi khác	Xem Danh sách mã lỗi.

QR Code động là giải pháp thanh toán tối ưu cho các giao dịch cần sự chính xác tuyệt đối. Mỗi mã QR được sinh ra riêng biệt cho từng đơn hàng, bao gồm thông tin thanh toán hoặc mã tham chiếu để hệ thống định danh giao dịch.

Trước khi bắt đầu
Base URL: https://uat-open-api.tingee.vn (UAT) · https://open-api.tingee.vn (PROD)
Xác thực: Mọi request cần gửi kèm các header x-client-id, x-request-timestamp và chữ ký x-signature (HMAC SHA512). Xem Hướng dẫn lấy API Key & sinh chữ ký.
Kết quả: API luôn trả về HTTP 200, kiểm tra trường code (00 = thành công). Xem Danh sách mã lỗi.
🆔 Định danh duy nhất
Mỗi QR gắn liền với một billId, giúp hệ thống tự động nhận diện và gạch nợ hóa đơn.

⌛ Hiệu lực linh hoạt
Hỗ trợ cấu hình thời gian hết hạn (Expire) để đảm bảo an toàn cho các giao dịch thanh toán nhanh.

💯 Đối soát tự động
Không phụ thuộc vào nội dung khách hàng nhập, hệ thống tự động khớp lệnh dựa trên dữ liệu QR.

API này cho phép tạo mã QR động cho từng giao dịch cụ thể, hỗ trợ thanh toán một lần hoặc nhiều lần tùy theo cấu hình.

POST
https://open-api.tingee.vn/v1/generate-dynamic-qr
PROD
UAT

API tạo mã QR động cho từng giao dịch. Kết quả trả về bao gồm chuỗi mã QR và thông tin hóa đơn trên hệ thống.

Header Request
Header	Bắt buộc	Mô tả
Content-Type	✓	application/json
x-client-id	✓	Mã định danh của đối tác do TINGEE cung cấp.
x-signature	✓	Chữ ký xác thực HMAC SHA512. Xem thêm tại Cách sinh chữ ký.
x-request-timestamp	✓	Thời gian gửi request (format: yyyyMMddHHmmssSSS, múi giờ UTC+7)
Body Parameter
Trường	Kiểu	Bắt buộc	Mô tả
merchantId	number	~	ID của Merchant
(Bắt buộc nếu kết nối bằng tài khoản Master Merchant).
vaAccountNumber	string	✓	Số tài khoản ảo (VA) đã liên kết của Merchant, tối đa 50 ký tự.
qrCodeType	string	✓	Loại QR:
- dynamic-one-time-payment: QR thanh toán một lần.
- dynamic-recurring-payment: QR thanh toán nhiều lần.
bankBin	string	✓	Mã BIN ngân hàng của vaAccountNumber. Hỗ trợ: OCB (970448), MB (970422), BIDV (970418), VietinBank (970415), Vietcombank (970436), VPBank (970432), Bảo Kim (BAOKIM). Xem tại Danh sách ngân hàng hỗ trợ.
amount	number	✓	Số tiền cần thanh toán (VND, tối thiểu 1).
name	string	✕	Tên hiển thị của QR động. Chỉ áp dụng với Bảo Kim; nếu bỏ trống, hệ thống dùng tên chủ tài khoản.
purpose	string	✕	Nội dung thanh toán.
expireInMinute	number	~	Thời gian hết hạn QR động (phút), từ 1 đến 43200 (30 ngày). Mặc định 43200.
Bắt buộc đối với ngân hàng OCB (970448).
extraInfo	string	✕	Thông tin bổ sung do đối tác tự định nghĩa, tối đa 200 ký tự. Được trả lại trong API Truy vấn trạng thái QR động.

code	string	Mã kết quả (00 = Thành công).

data.qrAccount	string	Số tài khoản nhận tiền được mã hóa trong QR (tài khoản QR). Dùng cùng billId khi gọi API truy vấn trạng thái / xóa QR động.
data.billId	string	Mã định danh QR động (hóa đơn) trên hệ thống TINGEE. Định dạng phụ thuộc ngân hàng, ví dụ:
- BIDV, VietinBank: {tiền tố VA}QRD{mã ngẫu nhiên} (trùng với qrAccount).
- MB, Vietcombank, VPBank: bắt đầu bằng QRD.

- Bảo Kim: trùng với qrAccount.

Code	Mô tả	Hướng xử lý
1024	Số tài khoản ảo không tồn tại	Kiểm tra vaAccountNumber và bankBin khớp với tài khoản đã liên kết của Merchant.
1018	Loại tài khoản này chưa hỗ trợ QR động	OCB: tài khoản Cá nhân hoặc Doanh nghiệp; BIDV, VietinBank, VPBank: chỉ tài khoản Doanh nghiệp; Vietcombank: không hỗ trợ tài khoản Cá nhân. Dùng tài khoản phù hợp hoặc QR tĩnh.

1082	Tên hiển thị (name) không hợp lệ	Với Bảo Kim, name phải bắt đầu bằng tên tài khoản đã đăng ký; hoặc bỏ trống name.
1086, 1087, 1088	Ví Bảo Kim chưa được cấu hình hoặc chưa đồng bộ	Hoàn tất cấu hình ví Bảo Kim trước khi tạo QR động.
1095, 1096	Lỗi merchantId của Master Merchant	Truyền merchantId của Merchant con thuộc Master Merchant đang gọi API.
90, 91, 92, 97	Lỗi xác thực request (timestamp, client-id, chữ ký)	Xem Mã lỗi hệ thống.

Sau khi người dùng hoàn tất thao tác trên ứng dụng ngân hàng, hệ thống Tingee sẽ tự động chuyển hướng người dùng quay trở lại ứng dụng hoặc website của đối tác kèm theo thông tin kết quả giao dịch.

Hệ thống Tingee sẽ append kết quả giao dịch trực tiếp vào redirectUrl dưới dạng Query String.

Các tham số được đính kèm vào URL chuyển hướng.

Tham số	Kiểu	Mô tả

Quy tắc xác thực
Để đảm bảo an toàn, đối tác phải kiểm tra chữ ký signature nhận được. Chữ ký được tạo như sau:

Lấy toàn bộ tham số trên URL (trừ signature), trong đó amount và transactionDate ở dạng số, các tham số còn lại ở dạng chuỗi.
Sắp xếp các key theo bảng chữ cái và chuyển thành chuỗi JSON (không có khoảng trắng, không escape ký tự unicode hoặc /). Ví dụ: {"accountNumber":"0123456789","amount":100000,"bankBin":"970422","bankName":"MBB","clientId":"YOUR_CLIENT_ID","content":"Thanh toan don hang","deepLinkStatus":"success","transactionDate":1736930449000}.
Ký HMAC SHA512 chuỗi JSON trên với secretKey của đối tác, kết quả ở dạng hex.
Ví dụ mã nguồn xác thực
NestJS
C#
Java

import { createHmac } from 'crypto';

function verifySignature(query: Record<string, string>, secretKey: string): boolean {
  const { signature, ...data } = query;

  // Sắp xếp các key theo alphabet; amount và transactionDate ở dạng số
  const sorted: Record<string, any> = {};
  for (const key of Object.keys(data).sort()) {
    sorted[key] = key === 'amount' || key === 'transactionDate' ? Number(data[key]) : data[key];
  }

  const computedSig = createHmac('sha512', secretKey)
    .update(JSON.stringify(sorted))
    .digest('hex');

  return computedSig === signature;
}

POST
https://open-api.tingee.vn/v1/create-pos-bill
PROD
UAT

Tạo đơn hàng thanh toán trên máy POS Payoo. Kết quả trả về billId dùng để tra cứu, hủy đơn và đối soát Webhook.

Header Request
Header	Bắt buộc	Mô tả
Content-Type	✓	application/json
x-client-id	✓	Mã định danh của đối tác do TINGEE cung cấp.
x-signature	✓	Chữ ký xác thực HMAC SHA512. Xem thêm tại Cách sinh chữ ký.
x-request-timestamp	✓	Thời gian gửi request (format: yyyyMMddHHmmssSSS, múi giờ UTC+7)
Body Parameter
Trường	Kiểu	Bắt buộc	Mô tả
merchantId	number	~	ID của Merchant sở hữu máy POS.
Bắt buộc nếu kết nối bằng tài khoản Master Merchant.
bankBin	string	✓	Truyền cố định PAYOO.
vaAccountNumber	string	✓	Mã thiết bị POS Payoo đã liên kết (tối đa 50 ký tự).
amount	number	✓	Số tiền cần thanh toán (VND, số nguyên dương).
paymentMethod	string	✕	Phương thức thanh toán hiển thị trên máy POS:
- card: Thanh toán thẻ
- qr: Thanh toán bằng mã QR
Bỏ trống (hoặc giá trị khác) để máy POS cho phép khách hàng tự chọn.
purpose	string	✕	Nội dung thanh toán, hiển thị trên máy POS.
expireInMinute	number	✕	Thời gian hiệu lực của đơn hàng (phút), từ 1 đến 43200. Mặc định 43200 (30 ngày).
extraInfo	string	✕	Thông tin bổ sung của đối tác (tối đa 200 ký tự), được gửi kèm trong Webhook thanh toán.
Ví dụ mã nguồn
cURL
NestJS
C#
Java
PHP
curl --location --request POST 'https://open-api.tingee.vn/v1/create-pos-bill' \
--header 'accept: application/json' \
--header 'x-client-id: YOUR_CLIENT_ID' \
--header 'x-request-timestamp: 20240509154004003' \
--header 'x-signature: YOUR_SIGNATURE' \
--header 'Content-Type: application/json' \
--data '{
  "bankBin": "PAYOO",
  "vaAccountNumber": "POS00012345",
  "amount": 150000,
  "paymentMethod": "card",
  "purpose": "Thanh toan don hang DH001",
  "expireInMinute": 30,
  "extraInfo": "DH001"
}'

Response mẫu
{
  "code": "00",
  "message": "Success",
  "data": {
    "billId": "9f1c2b7e4a5d4c3b8e2f1a0b9c8d7e6f",
    "amount": 150000,
    "expireInMinute": 30,
    "purpose": "Thanh toan don hang DH001"
  }
}

Trường	Kiểu	Mô tả
code	string	Mã kết quả (00 = Thành công).
message	string	Thông điệp phản hồi.
data.billId	string	Mã đơn hàng (32 ký tự). Dùng để tra cứu, hủy đơn và đối soát Webhook thanh toán.
data.amount	number	Số tiền của đơn hàng.
data.expireInMinute	number	Thời gian hiệu lực của đơn hàng (phút); 43200 nếu không truyền khi tạo.
data.purpose	string	Nội dung thanh toán (không trả về nếu không truyền khi tạo).
Mã lỗi thường gặp
Code	Mô tả	Hướng xử lý
1024	Số tài khoản ảo không tồn tại	Máy POS chưa được liên kết với Merchant. Liên kết bằng Tạo/Liên kết số tài khoản với bankBin = "PAYOO".
1096	Merchant ID không được bỏ trống	Tài khoản Master Merchant cần truyền merchantId.
1095	Merchant không thuộc Master Merchant	Kiểm tra merchantId thuộc Master Merchant đang gọi API.
400	Lỗi từ Payoo hoặc dữ liệu không hợp lệ	message chứa mô tả lỗi chi tiết từ Payoo hoặc từ bước kiểm tra dữ liệu.
90, 91, 92, 97	Lỗi xác thực request (timestamp, client-id, chữ ký)	Xem Mã lỗi hệ thống.

API này dùng để khởi tạo yêu cầu thanh toán hóa đơn.

Trường hợp khách hàng yêu cầu cần xác thực trước khi tự động thanh toán, Tingee sẽ gửi Email/Thông báo Zalo về cho khách hàng.
Khách hàng không yêu cầu xác thực thanh toán, hóa đơn sẽ được tự động khấu trừ từ tài khoản của khách hàng.
POST
https://open-api.tingee.vn/v1/direct-debit/payment-bill
PROD
UAT

Thực hiện yêu cầu thanh toán hóa đơn từ tài khoản khách hàng đã liên kết. Hỗ trợ thanh toán tự động hoặc qua xác thực.

Header Request
Header	Bắt buộc	Mô tả
Content-Type	✓	application/json
x-client-id	✓	Mã định danh của đối tác do TINGEE cung cấp.
x-signature	✓	Chữ ký xác thực HMAC SHA512. Xem thêm tại Cách sinh chữ ký.
x-request-timestamp	✓	Thời gian gửi request (format: yyyyMMddHHmmssSSS, múi giờ UTC+7)
Body Parameter
Trường	Kiểu	Bắt buộc	Mô tả
requestId	string	✓	ID của request đến Tingee (UUID), duy nhất cho mỗi lần thanh toán.
Giá trị này được dùng làm transactionId của giao dịch trích nợ trên TINGEE.
subscriptionId	string	✓	ID tài khoản ngân hàng đã liên kết (UUID). Tài khoản phải đang ở trạng thái active.
tokenRef	string	✓	Mã tham chiếu tới tài khoản khách hàng.
amount	string	✓	Giá trị hóa đơn cần thanh toán (VND), truyền dạng chuỗi số. Ví dụ: "500000".
description	string	✓	Nội dung thanh toán.
partnerCode	string	✓	Đối tác trích nợ. Giá trị hợp lệ: one-pay.
serviceProviderName	string	✓	Tên Đối tác sử dụng dịch vụ (hiển thị trong thông báo xác nhận gửi cho khách hàng).
returnUrl	string	✓	Link redirect về đối tác sau khi hoàn tất.
accountNumber	string	✕	Số tài khoản của khách hàng.
Hệ thống luôn trích nợ từ tài khoản đã liên kết với subscriptionId.
additionalData	object	✕	Thông tin bổ sung (mã hóa đơn, tên khách hàng....).
Chuỗi JSON của object tối đa 500 ký tự. Trường billNumber (nếu có) được hiển thị là mã hóa đơn trong Email/Zalo xác nhận.

NestJS
C#

  "requestId": "550760e0-1cc2-44b9-85ba-eb318e228b4f",

  "amount": "500000",
  "description": "THANH TOAN HOA DON DV HD123456",
  "partnerCode": "one-pay",
  "serviceProviderName": "Công ty TMCP ABC",
  "returnUrl": "https://example.com"
}'

Response mẫu
Trường hợp tự động thanh toán (khách hàng không yêu cầu xác thực):

{
  "code": "00",
  "message": "Success",
  "data": {
    "code": "00",
    "status": "success",
    "transactionCode": "TXN-0123456789",
    "returnUrl": "https://example.com?message=Success&type=direct-debit-transaction"
  }
}

Trường hợp cần khách hàng xác thực (đã bật xác nhận qua Email/Zalo):

{
  "code": "00",
  "message": "Success",
  "data": {
    "code": "00",
    "isSentConfirmEmail": true,
    "isSentConfirmZalo": false
  }
}

Trường	Kiểu	Mô tả
code	string	Mã phản hồi (00 là thành công).
message	string	Thông báo chi tiết.
data.code	string	Kết quả xử lý yêu cầu thanh toán:
- 00: Thành công (hoặc đã gửi yêu cầu xác thực cho khách hàng).
- 01: Thất bại.
- 02: Đang xử lý.

Tingee sẽ gửi webhook về endpoint của đối tác khi xảy ra các sự kiện quan trọng trong quá trình sử dụng dịch vụ Direct Debit.

Webhook giúp Đối tác:

Đồng bộ trạng thái: Cập nhật kết quả thanh toán, liên kết tài khoản theo thời gian thực.
Tự động hóa: Chủ động xử lý nghiệp vụ ngay khi có thông báo từ hệ thống.
Đối tác cần cung cấp URL nhận webhook cho đội ngũ kỹ thuật Tingee để cấu hình trước khi bắt đầu tích hợp.

Luồng xử lý Webhook
Sự kiện: Xảy ra các hành động như Liên kết tài khoản, Thanh toán, Hủy liên kết, hoặc Cập nhật PTXN.
Gửi thông báo: Tingee gửi request POST chứa payload dữ liệu đến URL đã cấu hình.
Xác thực: Đối tác kiểm tra chữ ký x-signature trong Header để đảm bảo dữ liệu đến từ Tingee.
Xử lý & Phản hồi: Đối tác xử lý dữ liệu và phản hồi lại Tingee (Status code 200).
Retry: Nếu gửi thất bại, hệ thống Tingee sẽ tự động thử lại theo cơ chế Retry.

Luồng duyệt Maker/Checker áp dụng cho Ngân hàng BIDV yêu cầu quy trình bảo mật cao và duyệt lệnh nhiều cấp. Trong luồng này, lệnh chi hộ có thể được lưu nháp (INIT) hoặc đẩy duyệt trực tiếp (REQUEST_APPROVAL), sau đó bắt buộc phải thông qua bước xác thực mã SmartOTP trên thiết bị.

Đặc điểm của luồng
Lưu nháp (INIT): Giao dịch được lưu vào hệ thống, chưa đẩy sang ngân hàng. Lệnh ở trạng thái này có thể bị xóa bằng API Xóa lệnh chi hộ, hoặc có thể được duyệt sau đó bằng API Đẩy duyệt lệnh chi hộ đã lưu.
Đẩy duyệt (REQUEST_APPROVAL): Giao dịch được đẩy sang hệ thống ngân hàng ngay lập tức để lấy thông tin xác thực (mã QR/SmartOTP). Lệnh ở trạng thái này không thể xóa và phải được xác thực bằng API Xác thực lệnh chi.
Yêu cầu xác thực bảo mật 2 lớp qua mã SmartOTP.

Các API tham gia trong luồng
Để tích hợp hoàn chỉnh luồng Maker/Checker, bạn sẽ thao tác với các API sau:

Lấy đường dẫn xác thực:
Dùng để lấy link đăng nhập tài khoản BIDV. Bắt buộc phải thực hiện bước này (cho cả Maker và Checker) trước khi có thể gọi các API tiếp theo.
Khởi tạo lệnh chi hộ:
Dùng để Lưu nháp (action="INIT") hoặc đẩy duyệt ngay (action="REQUEST_APPROVAL").
Xóa lệnh chi:
Chỉ dùng được đối với các giao dịch đang ở trạng thái lưu nháp (INIT).
Đẩy duyệt lệnh chi hộ đã lưu:
Dùng để chuyển trạng thái lệnh nháp (INIT) sang trạng thái chờ duyệt (REQUEST_APPROVAL).
Xác nhận đẩy duyệt lệnh chi:
Là bước cuối cùng để hoàn tất giao dịch. Bắt buộc phải truyền mã SmartOTP từ App Chi hộ BIDV vào tham số otp để duyệt lệnh.
Duyệt lệnh chi hộ:
Dùng cho role Checker để khởi tạo quá trình phê duyệt lệnh chi. API sẽ trả về dữ liệu qrData để Checker quét bằng App Chi hộ BIDV và lấy mã OTP.
Xác nhận duyệt lệnh chi hộ:
Dùng để Checker xác nhận phê duyệt, bắt buộc truyền mã OTP thu được từ bước trên để hoàn tất việc duyệt lệnh.
Từ chối lệnh chi:
Dùng khi Checker muốn từ chối lệnh chi hộ. Lệnh sẽ bị hủy bỏ ngay lập tức và không yêu cầu xác thực OTP.
Truy vấn giao dịch:
Dùng cho Maker/Checker để kiểm tra và theo dõi trạng thái các lệnh chi hộ (chờ duyệt, đã duyệt, đã hạch toán, bị từ chối...) hoặc lấy danh sách các giao dịch con trong Lô theo trạng thái hợp lệ hoặc không hợp lệ.
Các lưu ý đặc thù của luồng Maker/Checker
💡 Đặc thù xử lý theo Loại nghiệp vụ (actionType)

Đối với Thanh toán Lương (SALARY) và Thanh toán Hóa đơn (BILL_PAYMENT): Lệnh chi hộ luôn được xử lý theo Lô (Batch) và chia sẻ chung một mã ID. Các thao tác khởi tạo, đẩy duyệt (của Maker) hay phê duyệt, từ chối (của Checker) sẽ tác động lên toàn bộ lô giao dịch.
Đối với Chuyển tiền trong nước (INTERNAL_TRANSFER): Lệnh chi hộ có thể xử lý dưới dạng Đơn hoặc Lô. Điểm đặc biệt của giao dịch Lô là các bản ghi bên trong hoạt động hoàn toàn độc lập với mã ID riêng biệt. Nhờ đó, hệ thống hỗ trợ cơ chế xử lý linh hoạt từng phần: Maker có thể chọn đẩy duyệt hoặc xóa một phần các giao dịch cụ thể; tương tự, Checker cũng có quyền phê duyệt hoặc từ chối một phần danh sách các giao dịch mà Maker đã đẩy lên thay vì phải xử lý toàn bộ lô.
💡 Đặc thù thời gian hạch toán theo Phương thức chuyển tiền

Chuyển tiền nhanh NAPAS 24/7: Ngay sau khi Checker thực hiện phê duyệt lệnh thành công, giao dịch sẽ được hệ thống ngân hàng BIDV hạch toán ngay lập tức.
Chuyển tiền Nội bộ BIDV và Chuyển tiền thường Liên ngân hàng: Sau khi Checker phê duyệt, giao dịch sẽ chuyển sang trạng thái chờ xử lý (Pending) và cần một khoảng thời gian nhất định để BIDV tiến hành hạch toán. Bạn cần chủ động gọi API Truy vấn giao dịch để cập nhật trạng thái cuối cùng.

Cấp độ chung (Global): Các trường như transactionType, feeMethod, effectiveDate và creditAccountType khi được truyền ở cấu trúc ngoài cùng của payload sẽ đóng vai trò là giá trị mặc định áp dụng cho tất cả các giao dịch bên trong danh sách `records`.
Cấp độ chi tiết (Record-level): Nếu các trường trên được chỉ định cụ thể cho từng phần tử trong mảng `records`, hệ thống sẽ ưu tiên sử dụng giá trị này, ghi đè lên giá trị mặc định ở cấp độ chung.

Cấu trúc Response data
Trường	Kiểu	Mô tả
status	string	Trạng thái của lệnh chi:
- SUCCESS: Lưu nháp thành công (action = INIT)
- PENDING_CONFIRMATION: Đã tạo lệnh đẩy duyệt, chờ xác nhận OTP qua API Xác nhận lệnh chi hộ với confirmId
- PARTIALLY_VALID: Lưu nháp thành công nhưng lô có bản ghi không hợp lệ (chỉ SALARY / BILL_PAYMENT)
- REQUIRES_CONFIRMATION: BIDV trả về cảnh báo cần xác nhận trước khi tiếp tục (chỉ SALARY / BILL_PAYMENT); nội dung cảnh báo nằm ở message. Gửi lại đúng payload cũ trong vòng 5 phút để xác nhận và tiếp tục tạo lệnh.
message	string	Nội dung cảnh báo từ BIDV (chỉ trả về khi status = REQUIRES_CONFIRMATION).
batchId	string	Mã lô giao dịch (chỉ trả về khi tạo lệnh chi lô INTERNAL_TRANSFER hoặc lệnh SALARY / BILL_PAYMENT). Dùng cho API Tải file kết quả chi lô và truy vấn BATCH_UPLOAD_INQUIRY.
confirmId	string	Chuỗi key xác nhận giao dịch (chỉ trả về khi tạo lệnh đẩy duyệt REQUEST_APPROVAL).
transactionId	string	Mã giao dịch cấp lô (chỉ SALARY / BILL_PAYMENT) — dùng cho các API đẩy duyệt, duyệt, từ chối, xóa và truy vấn chi tiết.
transactionCode	string	Mã loại giao dịch phía ngân hàng (chỉ SALARY / BILL_PAYMENT).
totalRecords	number	Tổng số giao dịch.
validRecords	number	Số lượng giao dịch hợp lệ.
invalidRecords	number	Số lượng giao dịch không hợp lệ.
requireAuth	boolean	Yêu cầu xác thực giao dịch thêm (VD: SmartOTP) (chỉ INTERNAL_TRANSFER).
transAuth	object	Thông tin cấu hình xác thực (có giá trị khi cần xác thực thêm, ngược lại là null).
records	array	Danh sách kết quả chi tiết từng giao dịch (Với lệnh chi lô đẩy duyệt REQUEST_APPROVAL, mảng này sẽ rỗng do chưa có kết quả xử lý của từng lệnh con).
Lô có bản ghi không hợp lệ
Với lệnh chi lô INTERNAL_TRANSFER và lệnh SALARY / BILL_PAYMENT, nếu BIDV kiểm tra file lô và phát hiện bản ghi không hợp lệ, API trả về code = "400" kèm data gồm batchId, validRecords, invalidRecords. Dùng Truy vấn giao dịch với inquiryType = BATCH_UPLOAD_INQUIRY, batchId tương ứng và status = INVALID để xem lỗi chi tiết từng bản ghi.

Hướng dẫn xác thực SmartOTP (Đẩy duyệt BIDV)
Khi đẩy duyệt giao dịch, nếu hệ thống trả về requireAuth: true kèm theo transAuth.qrData, bạn cần thực hiện các bước sau để lấy mã OTP:

Chuyển đổi chuỗi ký tự trong qrData thành một hình ảnh mã QR (QR Code image).
Mở ứng dụng BIDV Direct trên thiết bị (đã được cấp quyền duyệt lệnh).
Sử dụng tính năng quét mã QR trong ứng dụng để quét hình ảnh QR vừa tạo.
Kiểm tra kỹ thông tin giao dịch trên màn hình ứng dụng và xác nhận bằng mã PIN của BIDV Direct.
Sau khi xác nhận mã PIN, một mã SmartOTP sẽ được hiển thị trên màn hình.
Lấy mã SmartOTP này truyền vào tham số otp trong API Xác nhận lệnh chuyển khoản để hoàn tất giao dịch.
